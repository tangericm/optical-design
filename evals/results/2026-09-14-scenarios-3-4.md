# Scenarios 3 and 4 baselines

Run 2026-09-14 on branch `adoption-review-cleanup` (skill at 2.0.0). One Sonnet agent with
the skill, one without (forbidden to read `skills/` or `docs/`). Both agents in each pair
were told mid-run to cap the optimizer at about 50 function evaluations so the runs
would finish; results are partial optimizations, compared like for like.

## Scenario 3: rebalance the OCT semi-Plössl scan lens over 800 to 900 nm

Ground truth from `evals/check_first_order.py`: EFL 35.973 / 36.000 / 36.039 mm at
800 / 840 / 900 nm (spread 66 um); image-space chief-ray angle at 6 degrees, 840 nm:
0.0036 degrees; EPD 4.0 mm.

| Assertion | With skill | Without skill |
|---|---|---|
| Baseline chromatic focal shift within 1 % of the per-wavelength EFL spread | pass (66.1 um) | partial: reported 57.8 um best-focus spread, a different definition |
| Spot size at 0, 4.2, 6 degrees before and after, tagged | pass (102/119/138 um to 10.6/10.0/15.2 um) | pass (100/117/135 um to 12.5/7.7/14.0 um) |
| Telecentricity within 1 % of the checker's figure | pass (0.00361 degrees reproduced; worst over band 0.033 to 0.020 degrees) | partial: reported only worst-case over band (0.033 to 0.0014 degrees) |
| EPD 4 mm and +/-6 degree scan confirmed after optimization | pass | pass |
| Variables named, numeric improvement | pass (six radii, air gap, back focus; merit 95x) | pass (six radii, air gap, back focus; cost 118x) |
| Inputs unmodified | pass | pass |
| Wall clock | 25.6 min | 18.2 min |

Both optimizations reached near-diffraction-limited spots. The skill run's numbers line up
with the checker's definitions because it used the same first-order tools; the baseline
run's numbers are defensible but not comparable without re-deriving them. The skill run
also reported the honest downside (chromatic shift grew from 66 to 90 um) and named the
next move (open one glass); the baseline run reported a 2.8x improvement in a spread it
defined itself.

## Scenario 4: least squares on the Cooke triplet, EFL held within 1 %

| Assertion | With skill | Without skill |
|---|---|---|
| Real merit-function optimizer with named operands and variables | pass (LeastSquares, 50 evaluations) | pass (LeastSquares, 50 evaluations) |
| RMS spot at three fields before and after, with wavelengths, in um | pass (4.88/17.26/12.94 to 4.66/17.01/13.19) | pass (5.00/15.93/12.23 to 4.72/15.50/12.84) |
| EFL before and after within 1 % | pass (50.0004 to 49.9989 mm) | pass (50.0004 to 49.9960 mm) |
| Variables released and held stated | pass (six curvatures, two air gaps; glass, thickness, BFL fixed) | pass (six curvatures; all else fixed) |
| Trade-off named in Seidel terms with direction | pass: coma and astigmatism down, distortion up 5.7 %, spherical and Petzval untouched because stop-shift invariant and air gaps cannot reach them; Petzval named as the limit | pass with a flaw: names the same terms, then attributes edge-field spot growth to distortion, which displaces but does not blur |
| Inputs unmodified | pass | pass |
| Wall clock | 25.1 min | 17.5 min |

Equal on assertions; the skill run's reasoning is physically consistent and the baseline's
is not. Neither run converged in 50 evaluations (merit down about 2 percent), so the
scenario as written needs a larger budget or a smaller variable set to show a real result.

Where the skill helps: the first-order gate keeps NA, EFL and pupil numbers consistent
with the file; metric definitions match the checker; explanations follow the aberration
primer; trade-offs and next moves are stated. Where it costs: the full before-and-after
figure set adds time on optimization scenarios. Two things to fix in the eval harness:
exclude `evals/` from the installed skill so with-skill agents cannot read the rubric, and
give scenarios 3 and 4 an explicit optimizer budget in the query.
