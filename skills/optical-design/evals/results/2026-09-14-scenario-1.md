# Scenario 1 baseline: achromat first-order and diagnosis

Run 2026-09-14 on branch `adoption-review-cleanup` (skill at commit a3ef11f). One Sonnet
agent with the skill installed, one without (forbidden to read `skills/` or `docs/`,
allowed any public library). Same query, same file. Ground truth from
`evals/check_first_order.py`: EFL 50.000 mm, BFL 45.164 mm, F/5.00, EPD 10 mm, total track
52.664 mm at 587.6 nm.

| Assertion | With skill | Without skill |
|---|---|---|
| First-order values within 1 %, with units | pass | pass |
| Wavelength stated for every number | pass | pass |
| Diagnosis backed by fan, Seidel or spot evidence | pass (Seidel table, ray fans, spot grid) | pass (Seidel table, ray fans) |
| No F-number / NA or sign confusion | pass | pass |
| Source file byte-identical, work on a copy | pass | pass |
| Wall clock | 4.9 min | 11.1 min |
| Agent tokens | 106 k | 115 k |
| Tools used | `inspect_zmx.py`, `first_order.py`, recipes 4, 5, 7, `diagnosis.md` | hand-written Optiland script after API exploration |

Both agents reached the correct numbers. The diagnoses agree on the evidence (S_I is the
largest Seidel sum on axis; fans turn comatic off axis) and differ only in emphasis: the
with-skill run separated on-axis spherical from off-axis coma; the without-skill run named
coma as dominant. A capable model already knows Optiland, so on this scenario the skill's
measurable gain is speed (2.3x) and the structured evidence order, not correctness. Harder
scenarios (3, 4, 5) are where the merit recipe, first-order gate and tolerancing recipe
should separate the runs; they have not been run yet.
